📋项目概述

CodeBuddy Wireless 是一个为 AI 编程场景设计的无线外设系统，将 DFRobot UNIHIKER K10 开发板改造为集成无线麦克风、无线键盘和实时状态显示的三合一智能设备。

🎯 核心价值

🎙️ 无线语音输入

I2S 数字麦克风 (ES7243E) → ESP-NOW 2.4GHz 传输 → USB Audio 输入 PC，支持 Claude Code、Cursor 等 AI 编程工具的语音交互

⌨️ 无线快捷键盘

物理按键 A/B 映射 F2/Enter/Backspace，通过 USB HID 协议控制 PC，支持短按/长按/组合键，优化文件重命名等高频操作

📊 实时状态显示

240×320 LCD 显示 AI 服务 Token 配额、项目进度、灵感笔记、用户信息、AI 工作状态等六个界面，LVGL 驱动，支持 SD 卡图片

✅ 已验证功能： 音频流、按键功能、六界面 UI 渲染、演示模式（模拟数据注入）、SD 卡图片加载

数据流向

音频流路径

ES7243E I2S 麦克风 → K10 ESP32-S3 DMA 缓冲 → 下混为单声道 → ESP-NOW 音频帧 (0x02) → Dongle 环形缓冲 → USB Audio (UAC 1.0, 16kHz mono) → PC 录音设备

按键流路径

物理按键 A/B → XL95x5 IO 扩展 → K10 边沿检测 → HID 键码映射 → ESP-NOW 按键帧 (0x01) → Dongle HID 报告 → PC 键盘输入

状态流路径（未来）

PC 上位机程序（读取 AI 软件状态）→ USB 串口 → Dongle 转发 → ESP-NOW 状态帧 (0x07/0x08/0x09) → K10 解析 → 刷新对应 LVGL 界面

⚠️ 技术约束：Windows WiFi 网卡无法直接发送 ESP-NOW 帧（标准驱动不支持原始帧注入），状态数据必须通过 ESP32 设备（Dongle）中转。

✨核心功能详解

🎙️ 无线麦克风功能 ▼

技术实现

  • 硬件: ES7243E I2S 数字麦克风 ADC，I2C 地址 0x11
  • 采样: 16kHz 立体声，I2S DMA 模式，512 采样缓冲
  • 下混: 左右声道求平均，转换为单声道
  • 打包: 128 字节音频帧（64 采样 × 2 字节），帧类型 0x02
  • 传输: ESP-NOW 发送，约 250 帧/秒，CRC8 校验
  • 接收: Dongle 环形缓冲 → USB Audio Class 1.0 (16kHz mono)

触发方式

按键 A 短按切换音频流开关，LED 指示灯状态同步。

性能指标

  • 端到端延迟: < 50ms
  • 包成功率: > 99% (近距离 3 米内)
  • 带宽占用: ~32 kbps
⌨️ 无线键盘功能 ▼

按键映射表

按键 短按 (<600ms) 长按 (≥600ms) 组合键

边沿检测原理

  • 按下时记录时间戳，不立即发送
  • 释放时计算持续时间判断短按/长按
  • 长按期间每 100ms 重复发送（按键 B）
  • 组合键优先检测，避免误触发单键逻辑

应用场景

文件重命名优化: 选中文件 → A 短按进入重命名 (F2) → 输入新名称 → A 长按确认 (Enter) / B 长按连续删除 (Backspace)

📊 状态显示功能 ▼

LVGL 配置

  • 版本: LVGL 8.3.11
  • 分辨率: 240×320, 16-bit color (RGB565)
  • 缓冲: PSRAM 双缓冲，DMA 传输
  • 字体: Montserrat 12/14/16/18/20/28/32
  • PNG 解码: LVGL 内置 libpng

SD 卡文件系统

  • 协议: SPI HSPI 模式，1MHz 时钟
  • 格式: FAT32 (exFAT 不支持)
  • 驱动: 自定义 LVGL 文件系统桥接 (驱动器盘符 'D:')
  • 图片: D:/user.png (240×320), D:/ai.png

降级机制

SD 卡初始化失败时，界面 4 显示渐变色块，界面 5 显示旋转弧形动画，不影响其他功能。

📡ESP-NOW 通信协议

协议定义在 espnow_protocol.h，K10 与 Dongle 必须保持一致。

帧类型一览

类型码 名称 长度 方向 用途
0x01 KEY 13 字节 K10 → Dongle 按键事件（按下/释放）
0x02 AUDIO 133 字节 K10 → Dongle 音频数据（64 采样）
0x04 PAIR - 双向 配对请求（预留）
0x06 HEARTBEAT - 双向 心跳包（预留）
0x07 TOKEN_STATUS 154 字节 Dongle → K10 Token 配额状态（最多 5 项）
0x08 PROJECT_STATUS 154 字节 Dongle → K10 项目进度状态（最多 6 项）
0x09 AI_EMOTION 24 字节 Dongle → K10 AI 情感状态（预留）

关键帧结构

🔑 按键帧 (0x01) ▼ 
typedef struct __attribute__((packed)) {
    uint8_t  frame_type;   // = 0x01
    uint8_t  action;       // 1=按下, 0=释放
    uint8_t  modifier;     // HID 修饰键掩码 (Ctrl/Shift/Alt)
    uint8_t  keycode[6];   // HID 键码，最多 6 键同时按下
    uint16_t timestamp;    // 时间戳 (ms 低 16 位)
    uint8_t  seq_num;      // 序列号
    uint8_t  crc8;         // CRC8 校验
} key_frame_t;  // 13 字节

HID 键码: 0x3B (F2), 0x28 (Enter), 0x2A (Backspace)

🎵 音频帧 (0x02) ▼ 
typedef struct __attribute__((packed)) {
    uint8_t  frame_type;        // = 0x02
    uint8_t  seq_num;           // 序列号
    uint16_t timestamp;         // 时间戳
    uint8_t  audio_data[128];   // 128 字节 PCM (64 采样 × 2 字节)
    uint8_t  crc8;
} audio_frame_t;  // 133 字节

音频格式: 16kHz 单声道, 16-bit 有符号整数, 小端序

📊 Token 状态帧 (0x07) ▼ 
typedef struct __attribute__((packed)) {
    char     name[20];       // 服务名, 如 "OpenAI Codex"
    uint32_t used;           // 已用 token (小端序)
    uint32_t total;          // 总配额 (小端序)
    uint16_t percent_x10;    // 百分比×10 (847 = 84.7%)
} token_item_t;  // 30 字节

typedef struct __attribute__((packed)) {
    uint8_t      frame_type;  // = 0x07
    uint8_t      count;       // 有效条目数 (1~5)
    uint8_t      seq_num;
    token_item_t items[5];    // 5 × 30 = 150 字节
    uint8_t      crc8;
} token_status_frame_t;  // 154 字节
🚀 项目状态帧 (0x08) ▼ 
typedef enum {
    PROJ_STATUS_PLANNING   = 0x00,  // 蓝色
    PROJ_STATUS_CODING     = 0x01,  // 紫色
    PROJ_STATUS_REVIEW     = 0x02,  // 橙色
    PROJ_STATUS_COMPLETED  = 0x03,  // 绿色
    PROJ_STATUS_ERROR      = 0x04,  // 红色
    PROJ_STATUS_IDLE       = 0x05,  // 灰色
} project_status_code_t;

typedef struct __attribute__((packed)) {
    char    name[24];        // 项目名
    uint8_t status_code;     // project_status_code_t
} project_item_t;  // 25 字节

typedef struct __attribute__((packed)) {
    uint8_t        frame_type;  // = 0x08
    uint8_t        count;       // 有效条目数 (1~6)
    uint8_t        seq_num;
    project_item_t items[6];    // 6 × 25 = 150 字节
    uint8_t        crc8;
} project_status_frame_t;  // 154 字节

CRC8 校验算法

static inline uint8_t espnow_crc8(const uint8_t *data, size_t len) {
    uint8_t crc = 0x00;
    for (size_t i = 0; i < len; i++) {
        crc ^= data[i];
        for (uint8_t j = 0; j < 8; j++) {
            crc = (crc & 0x80) ? ((crc << 1) ^ 0x07) : (crc << 1);
        }
    }
    return crc;
}
// 多项式: 0x07, 初值: 0x00, 覆盖范围: 除最后 crc8 字节外的所有字节
⚠️ 协议一致性：espnow_protocol.h 必须在 K10 和 Dongle 两端保持完全一致，修改后两端都要重新编译。

关键配置 (lv_conf.h)

  • LV_IMG_CACHE_DEF_SIZE 4 — 关键: 无缓存时 PNG 每帧重新解码 (100+ms)，导致按键误检测
  • LV_USE_PNG 1 — 启用内置 PNG 解码器
  • LV_FONT_MONTSERRAT_12/14/16/18/20/28/32 1 — 自定义字体

线程安全

所有 LVGL 操作必须持有 xGuiSemaphore 互斥锁，防止竞态条件：

  • switch_screen() — 界面切换
  • update_screen_*() — 数据更新
  • lv_task_handler() — 渲染循环
  • 动画刷新 (100ms 定时器)
