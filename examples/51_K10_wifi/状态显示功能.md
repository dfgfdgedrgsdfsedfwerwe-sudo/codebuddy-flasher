# K10 AI 编程状态显示功能

**更新时间**: 2026-08-24  
**状态**: ✅ 六界面演示模式完成 + 三界面交互增强（Token 高亮/Inspo 打字/Profile 切换）

---

## 功能概述

在 K10 上显示 AI 编程相关的六个界面，包括实时状态、Token 配额、项目进度、灵感笔记、用户信息、AI 工作状态。**新增**三个界面的演示模式交互增强。

---

## 六界面结构

按键 B 短按循环切换（0 → 1 → 2 → 3 → 4 → 5 → 0）：

| 界面 | 名称 | 内容 | 数据来源 |
|------|------|------|---------|
| 0 | ESP-NOW Status | 连接状态 + 音频流状态 + 包计数 | 实时 |
| 1 | Token Usage | AI 服务 Token 配额（进度条+百分比+数量） | 演示模式 |
| 2 | Coding Status | 项目进度状态列表（彩色圆点+状态） | 演示模式 |
| 3 | **Product Inspo** | 产品灵感卡片（标题+日期+正文） | 演示模式 |
| 4 | **User Profile** | 用户信息（渐变色块+名字） | 演示模式 |
| 5 | **AI Status** | AI 工作状态（旋转动画+文字） | 演示模式 |

## 界面详细说明

### 界面 0: ESP-NOW Status（实时数据）
- ESP-NOW 连接状态（绿色 OK / 红色 FAILED）
- 通道号、对端 MAC 地址
- 音频流状态（REC 红色 / IDLE 青色）
- 已发送包数、失败包数

### 界面 1: Token Usage（演示数据 + 交互）
每行显示：服务名 + 百分比标签（带背景色块）+ 进度条 + 已用/总量

**颜色规则**：
- 百分比 < 80%：绿色（0x00FF88）
- 百分比 ≥ 80%：红色警告（0xFF4444）

**数字格式化**：大数字自动加千位逗号（847200 → "847,200"）

**演示数据**：
- OpenAI Codex: 84.7% (847,200 / 1,000,000)
- Claude Code Opus: 62.5% (312,500 / 500,000)
- Claude Code Sonnet: 62.3% (1,245,000 / 2,000,000)
- Cursor GPT-4: 39.2% (392,000 / 1,000,000)

**✨ 新增交互（演示模式专属）**：
- **A 短按**：循环高亮下一行（高亮行背景变浅灰 0x2A2A2A）
- **A 长按 (≥600ms)**：重置所有进度条到 10%，百分比归零
- **状态反馈**：重置后串口输出 `Token usage reset!`

### 界面 2: Coding Status（演示数据）

### 界面 3: Product Inspo（演示数据 + 交互）
产品灵感笔记卡片，深色背景，白色标题，灰色日期，浅色正文。

**演示数据**：
- 标题: "Product Inspo"
- 日期: "July 29, 2026"
- 正文: Lenovo CodeBuddy 产品介绍（多行自动换行）

**✨ 新增交互（演示模式专属）**：
- **进入界面时自动触发**：打字机动画 + 闪烁光标
  - 正文逐字显示（每字符间隔 40ms）
  - 光标每 500ms 闪烁一次（下划线 `_`）
  - 打字完成后光标继续闪烁
- **A 短按**：重启打字机动画（清空文本 → 重新逐字显示）
- **状态反馈**：串口输出 `Inspo typing restarted`

### 界面 4: User Profile（演示数据 + 交互）
用户信息展示，上方蓝紫渐变色块（代替照片），底部黄色用户名。

**演示数据**：

- 用户名: "Thomas B."（黄色 28号字体）

**✨ 新增交互（演示模式专属）**：
- **SD 卡检测**：启动时扫描 `D:/user.png`, `D:/user1.png`, `D:/user2.png` ... (最多 10 张)

  - 无 SD 卡：切换预设渐变色块（蓝紫/粉橙/青绿）
- **状态反馈**：串口输出 `Profile switched to: D:/userN.png` 或 `Profile switched (fallback)`

**演示数据**：

## 演示模式（本地验证用）

**触发**: 同时按住按键 A + B，保持 2 秒

**效果**: 
1. 注入所有模拟数据（Token、Project、Inspo、Profile、AI Status）
2. 自动跳转到界面 1（Token Usage）
3. 串口输出：`*** DEMO MODE ACTIVATED ***`

**用途**: 
- 零依赖展示所有六个界面的 UI 效果
- 无需电脑程序、无需 ESP-NOW 传输
- 纯本地验证，适合产品演示

**✨ 新增：演示模式专属交互**（仅在进入演示模式后生效）：
- **界面 1 (Token Usage)**: A 短按循环高亮 → A 长按重置进度
- **界面 3 (Product Inspo)**: 进入时自动打字机动画 → A 短按重启动画
- **界面 4 (User Profile)**: A 短按切换用户照片（SD 卡或 fallback 渐变）

## 数据协议 (espnow_protocol.h)

新增两种帧类型（用于未来真实数据推送）：
- `FRAME_TYPE_TOKEN_STATUS` (0x07): `token_status_frame_t`，最多 5 个服务，154 字节
- `FRAME_TYPE_PROJECT_STATUS` (0x08): `project_status_frame_t`，最多 6 个项目，154 字节

两帧均带 CRC8 校验，接收端 `espnow_recv_cb` 解析后自动刷新对应界面。

## 真实数据链路（可选，未实现）

```
Claude Code / Cursor 状态
    ↓ 电脑端程序读取（无法省略）
电脑 Python 脚本
    ↓ USB 串口
ESP32 桥（Dongle 或独立板）
    ↓ ESP-NOW 状态帧
K10 显示
```

**关键结论**: 
- 电脑 WiFi 网卡无法直接发 ESP-NOW（Windows 标准驱动不支持原始帧注入）
- 电脑端读取程序无法省略——Dongle 无法自己读懂电脑上 AI 软件的运行状态
- **当前演示模式已足够展示产品效果，真实数据推送为可选增强功能**
