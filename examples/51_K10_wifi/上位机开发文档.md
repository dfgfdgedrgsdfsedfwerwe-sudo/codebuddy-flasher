# CodeBuddy 上位机开发文档

**面向对象**: 集成 CodeBuddy 状态显示的软件开发团队
**版本**: v1.0
**日期**: 2026-08-21

---

## 1. 这份文档解决什么问题

CodeBuddy 是一个硬件设备（K10 屏幕 + Dongle USB 收发器）。K10 屏幕上有几个界面，可以显示 **AI 编程软件的实时状态**：

- **Token Usage**：各 AI 服务的 token 消耗（进度条 + 百分比）
- **Coding Status**：多个项目的进度状态（Planning/Coding/Review/Completed…）

这些数据**必须由你的软件（上位机）提供**。本文档告诉你：数据怎么组织、怎么发给设备、需要配合做哪些改动。

> 你只需要关注"如何把状态数据推送出去"，K10 屏幕的渲染已经做好了。

---

## 2. 整体架构（先理解数据怎么流动）

```
┌────────────────────┐
│  你的软件 (上位机)   │  ← 你要开发的部分
│  读取 AI 编程状态    │
└─────────┬──────────┘
          │  ① USB 串口 (发送状态帧字节流)
          ▼
┌────────────────────┐
│  Dongle (ESP32-S3) │  ← 需要新增"串口收→ESP-NOW转发"固件 (见第 6 节)
│  USB 复合设备       │
└─────────┬──────────┘
          │  ② ESP-NOW 无线 (2.4GHz)
          ▼
┌────────────────────┐
│   K10 (屏幕)        │  ← 已完成，无需改动
│  接收并显示状态      │
└────────────────────┘
```

### ⚠️ 两个必须先知道的关键约束

1. **上位机不能直接连 K10**。电脑 WiFi 网卡无法发 ESP-NOW（乐鑫私有 2.4GHz 协议，Windows 标准驱动不支持原始帧注入）。数据必须经 Dongle 中转。

2. **数据来源无法省略**。AI 软件（Claude Code / Cursor 等）的 token 用量、项目状态只存在于运行它的那台电脑本地。Dongle 和 K10 都无从得知，必须由你的软件主动读取（读日志文件 / 调 API / 抓取界面 / 内部埋点）后推送出去。

## 3. 你需要做的三件事

| # | 工作 | 说明 |
|---|------|------|
| A | **读取状态数据** | 从你的 AI 软件获取 token 用量、项目状态。数据来源由你决定（内部 API 最佳） |
| B | **打包成协议帧** | 按第 4 节的字节格式封装（含 CRC8 校验） |
| C | **通过串口发送** | 打开 Dongle 的 USB 串口，写入帧字节 |

另外需要配合固件团队完成 Dongle 的转发固件（第 6 节），这部分不是上位机的活，但你需要知道接口。

## 4. 数据协议格式（核心）

所有多字节整数为**小端序 (little-endian)**，结构体**紧凑排列无对齐填充**（等价于 C 的 `__attribute__((packed))`）。

### 4.1 Token 使用状态帧（154 字节）

一帧最多携带 5 个 AI 服务。

**帧头（3 字节）**
| 偏移 | 字段 | 类型 | 值 |
|------|------|------|-----|
| 0 | frame_type | uint8 | `0x07`（固定） |
| 1 | count | uint8 | 有效条目数 0~5 |
| 2 | seq_num | uint8 | 序列号，每帧递增（0~255 循环） |

**条目数组（5 × 30 = 150 字节）**，每个条目 30 字节：
| 偏移 | 字段 | 类型 | 说明 |
|------|------|------|------|
| +0 | name | char[20] | 服务名，UTF-8，不足补 `\0`，最长 19 字符 |
| +20 | used | uint32 | 已用 token 数 |
| +24 | total | uint32 | 总配额 |
| +28 | percent_x10 | uint16 | 百分比 ×10（如 84.7% → 847） |

**帧尾（1 字节）**
| 偏移 | 字段 | 类型 | 说明 |
|------|------|------|------|
| 153 | crc8 | uint8 | 对前 153 字节做 CRC8（见 4.3） |

> 即使 count < 5，也要发送完整 154 字节（未用条目填 0）。

### 4.2 项目状态帧（154 字节）

一帧最多携带 6 个项目。

**帧头（3 字节）**
| 偏移 | 字段 | 类型 | 值 |
|------|------|------|-----|
| 0 | frame_type | uint8 | `0x08`（固定） |
| 1 | count | uint8 | 有效条目数 0~6 |
| 2 | seq_num | uint8 | 序列号 |

**条目数组（6 × 25 = 150 字节）**，每个条目 25 字节：
| 偏移 | 字段 | 类型 | 说明 |
|------|------|------|------|
| +0 | name | char[24] | 项目名，UTF-8，补 `\0`，最长 23 字符 |
| +24 | status_code | uint8 | 状态码（见下表） |

**status_code 取值**：
| 值 | 含义 | 屏幕圆点颜色 |
|----|------|-------------|
| 0 | Planning | 蓝 |
| 1 | Coding | 紫 |
| 2 | Review Needed | 橙 |
| 3 | Completed | 绿 |
| 4 | Error | 红 |
| 5 | Idle | 灰 |

**帧尾**：偏移 153，crc8。

### 4.3 CRC8 算法

多项式 `0x07`，初值 `0x00`，覆盖帧内除最后 1 字节（crc8 本身）外的所有字节。

参考实现（Python）：
```python
def crc8(data: bytes) -> int:
    crc = 0x00
    for b in data:
        crc ^= b
        for _ in range(8):
            crc = ((crc << 1) ^ 0x07) & 0xFF if (crc & 0x80) else ((crc << 1) & 0xFF)
    return crc
```

## 5. 上位机参考实现（Python 示例）

以下示例演示如何打包并通过串口发送。**数据读取部分（`get_token_data` 等）需你替换为真实来源。**

```python
import struct, serial, time

def crc8(data: bytes) -> int:
    crc = 0
    for b in data:
        crc ^= b
        for _ in range(8):
            crc = ((crc << 1) ^ 0x07) & 0xFF if (crc & 0x80) else ((crc << 1) & 0xFF)
    return crc

def build_token_frame(items, seq):
    # items: list of (name:str, used:int, total:int)  最多5个
    buf = bytearray()
    buf += struct.pack('<BBB', 0x07, len(items), seq & 0xFF)
    for i in range(5):
        if i < len(items):
            name, used, total = items[i]
            pct10 = int(used * 1000 / total) if total else 0
            nb = name.encode('utf-8')[:19]
            nb += b'\x00' * (20 - len(nb))
            buf += nb + struct.pack('<IIH', used, total, pct10)
        else:
            buf += b'\x00' * 30
    buf.append(crc8(bytes(buf)))
    return bytes(buf)   # 恰好 154 字节

def build_project_frame(items, seq):
    # items: list of (name:str, status_code:int)  最多6个
    buf = bytearray()
    buf += struct.pack('<BBB', 0x08, len(items), seq & 0xFF)
    for i in range(6):
        if i < len(items):
            name, code = items[i]
            nb = name.encode('utf-8')[:23]
            nb += b'\x00' * (24 - len(nb))
            buf += nb + struct.pack('<B', code)
        else:
            buf += b'\x00' * 25
    buf.append(crc8(bytes(buf)))
    return bytes(buf)   # 恰好 154 字节

# ==== 替换成你的真实数据源 ====
def get_token_data():
    return [("OpenAI Codex", 847200, 1000000),
            ("Claude Opus", 312500, 500000)]
def get_project_data():
    return [("Smart Todo App", 2), ("AI Chat", 0)]  # 2=Review, 0=Planning

def main():
    ser = serial.Serial('COM6', 115200, timeout=1)  # Dongle 串口号
    seq = 0
    while True:
        ser.write(build_token_frame(get_token_data(), seq))
        time.sleep(0.05)
        ser.write(build_project_frame(get_project_data(), seq))
        seq = (seq + 1) & 0xFF
        time.sleep(2)   # 每 2 秒推送一次

if __name__ == '__main__':
    main()
```

### 发送频率建议
- 状态数据变化不频繁，**每 1~2 秒推一次**即可，不要高频刷。
- 每次把 Token 帧和 Project 帧都发一遍（两帧独立）。

## 6. Dongle 固件需要新增的部分（给固件团队）

> ⚠️ **当前 Dongle 固件只实现了单向接收**（K10→Dongle→USB HID/Audio），**没有** USB 串口收数据、也**没有** ESP-NOW 反向发送到 K10 的能力。这部分需要新开发。

固件团队需在 `dongle_firmware/` 中新增：

1. **USB 串口 (CDC/JTAG) 接收**：从 PC 读取上位机发来的字节流。按帧头字节判定长度切帧：`0x07`/`0x08` → 154 字节，`0x09` → 24 字节。
2. **ESP-NOW 反向发送**：Dongle 添加 K10 (`3c:dc:75:6d:7f:b4`) 为 peer，把收到的状态帧原样 `esp_now_send()` 给 K10。
3. **协议一致性**：`dongle_firmware/main/espnow_protocol.h` 已与 K10 的 `examples/51_mic_wifi/espnow_protocol.h` **完全一致**（含 0x07/0x08/0x09 三种帧、CRC8）。改动任一端务必同步另一端。

K10 接收端已就绪（`espnow_recv_cb` 已能解析 `0x07`/`0x08`/`0x09` 帧并刷新界面/表情），Dongle 转发到位后即可显示。

## 8. AI 情绪状态帧（驱动云朵表情，24 字节）

K10 的 **AI Status 界面**是一只会眨眼、动嘴的云朵，有三种情绪表情。默认情况下设备**本地自动循环** Thinking→Coding→Done。你可以发送 **AI 情绪帧** 让表情**跟随真实 AI 状态**（例如 AI 思考时显示 Thinking、生成代码时显示 Coding、完成时显示 Done）。

### 8.1 帧格式（`frame_type = 0x09`，固定 24 字节）

| 偏移 | 字段 | 类型 | 说明 |
|------|------|------|------|
| 0 | frame_type | uint8 | `0x09`（固定） |
| 1 | emotion | uint8 | 情绪码（见下表） |
| 2 | seq_num | uint8 | 序列号 |
| 3 | text | char[20] | 自定义显示文字，UTF-8，补 `\0`；**首字节为 `\0` 时用该情绪的默认文字** |
| 23 | crc8 | uint8 | 对前 23 字节做 CRC8 |

**emotion 情绪码**：
| 值 | 情绪 | 云朵表情 | 默认文字 |
|----|------|----------|----------|
| 0 | Thinking | 挑眉 + 闭嘴 | "Thinking..." |
| 1 | Coding | 皱眉 + 说话动嘴 | "Coding..." |
| 2 | Done | 平眉 + 微笑 | "Done!" |

### 8.2 行为说明

- 发送情绪帧后，K10 **立即切到该表情并停止本地自动循环**（进入"上位机驱动"模式）。
- `text` 非空时显示你的自定义文字（如 "Generating..."、"Reviewing PR"），最长 19 字符；为空则显示该情绪的默认文字。
- **超时保护**：若 K10 连续 **15 秒**未收到情绪帧，自动恢复本地循环。因此若要持续接管表情，**建议每 3~10 秒重发一次**当前情绪帧（心跳式）。

### 8.3 Python 示例

```python
def build_ai_state_frame(emotion, seq, text=""):
    # emotion: 0=Thinking 1=Coding 2=Done; text: 自定义文字(可空)
    buf = bytearray()
    buf += struct.pack('<BBB', 0x09, emotion, seq & 0xFF)
    tb = text.encode('utf-8')[:19]
    tb += b'\x00' * (20 - len(tb))
    buf += tb
    buf.append(crc8(bytes(buf)))
    return bytes(buf)   # 恰好 24 字节

# 用法: AI 开始思考
ser.write(build_ai_state_frame(0, seq))                 # Thinking, 默认文字
# AI 正在生成代码, 自定义文字
ser.write(build_ai_state_frame(1, seq, "Generating..."))
# 完成
ser.write(build_ai_state_frame(2, seq, "Done!"))
```

## 10. 常见问题

**Q: 为什么 K10 界面显示 "Waiting for data..."？**
A: K10 没收到状态帧。检查：Dongle 转发固件是否就绪、串口是否发送成功、帧格式/CRC 是否正确、信道 MAC 是否匹配。

**Q: 数字显示乱码或明显错误？**
A: 大概率是字节序或结构体对齐问题。确认用小端、无填充、字段偏移与第 4 节表格一致。

**Q: 名称显示被截断？**
A: Token 名称上限 19 字符，项目名上限 23 字符（各留 1 字节结尾 `\0`）。

**Q: 可以只发 Token 不发 Project 吗？**
A: 可以，两帧独立。只发你需要显示的那种。
