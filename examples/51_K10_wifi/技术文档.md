## 1. 系统概述

K10 固件是 CodeBuddy 无线系统的发射端，集三大功能于一体：

1. **无线麦克风**: I2S 采集板载麦克风 → ESP-NOW 发送到 Dongle → USB 音频输入到 PC ✅ 已验证
2. **无线键盘**: 物理按键 → ESP-NOW 按键帧 → Dongle → USB HID 到 PC ✅ 已验证
3. **状态显示**: LVGL 六界面 UI，展示 AI 编程相关信息（Token/项目/灵感/用户/AI状态）✅ UI 已验证，⚠️ 目前为模拟数据，真实数据待上位机程序（见第 8.3 节）

```
                    ┌─────────────────────────────┐
                    │        K10 (本固件)          │
                    │  ┌────────┐  ┌────────────┐  │
   麦克风声音 ──────►│  │  I2S   │  │   LVGL     │  │
                    │  │ ES7243E│  │  六界面UI   │◄─┼── SD卡图片
                    │  └───┬────┘  └────────────┘  │
   物理按键 A/B ────►│      │         ▲            │
                    │      ▼         │ (接收状态帧) │
                    │  ┌──────────────────────┐    │
                    │  │      ESP-NOW          │    │
                    │  └──────────┬───────────┘    │
                    └─────────────┼────────────────┘
                                  │ 2.4GHz 无线
                    ┌─────────────▼────────────────┐
                    │         Dongle                │
                    │  ESP-NOW接收 → USB HID+Audio  │
                    └─────────────┬─────────────────┘
                                  │ USB
                              ┌───▼───┐
                              │  PC   │
                              └───────┘
```

## 2. 硬件配置

### 2.1 引脚定义

| 功能 | 引脚 | 说明 |
|------|------|------|
| **I2S MCLK** | GPIO 3 | 麦克风主时钟 |
| **I2S BCLK** | GPIO 0 | 位时钟 |
| **I2S WS** | GPIO 38 | 字选择 (LRCK) |
| **I2S DIN** | GPIO 39 | 麦克风数据输入 |
| **I2S DOUT** | GPIO 45 | 功放输出（共用总线，本固件不写） |
| **SD CS** | GPIO 40 | SD 卡片选 |
| **SD MOSI** | GPIO 42 | SD 数据输出 |
| **SD MISO** | GPIO 41 | SD 数据输入 |
| **SD SCLK** | GPIO 44 | SD 时钟 |
| **I2C SDA** | GPIO 47 | 主 I2C（ES7243E + XL95x5） |
| **I2C SCL** | GPIO 48 | 主 I2C |
| **LCD** | GPIO 12/13/14/21 | SCLK/DC/CS/MOSI（⚠️ 禁止 I2C 扫描） |

### 2.2 关键芯片

- **ES7243E**: 麦克风 ADC，I2C 地址 `0x11`，需 45 寄存器初始化序列
- **XL95x5**: IO 扩展芯片，管理按键 A/B、LCD 背光（通过 `initBoard.h` 的 BSP 抽象）
- **SD 卡**: SPI HSPI 模式，1MHz 时钟

### 2.3 网络参数

| 参数 | 值 |
|------|-----|
| K10 MAC | `3c:dc:75:6d:7f:b4` |
| Dongle MAC | `e0:72:a1:d4:8f:e0` |
| WiFi 信道 | 1 |
| ESP-NOW 加密 | 无 |

## 4. ESP-NOW 协议 (espnow_protocol.h)

### 4.1 帧类型

```c
typedef enum {
    FRAME_TYPE_KEY   = 0x01,   // 按键事件帧
    FRAME_TYPE_AUDIO = 0x02,   // 音频数据帧
    FRAME_TYPE_FEC   = 0x03,   // 音频 FEC 冗余帧
    FRAME_TYPE_PAIR  = 0x04,   // 配对请求帧
    FRAME_TYPE_PAIR_ACK = 0x05,// 配对响应帧
    FRAME_TYPE_HEARTBEAT = 0x06,// 心跳帧
    FRAME_TYPE_TOKEN_STATUS = 0x07,   // Token 使用状态帧
    FRAME_TYPE_PROJECT_STATUS = 0x08, // 项目状态帧
} frame_type_t;
```

### 4.2 关键帧结构

**按键帧 (13 字节)**
```c
typedef struct __attribute__((packed)) {
    uint8_t  frame_type;   // = FRAME_TYPE_KEY
    uint8_t  action;       // 1=按下, 0=释放
    uint8_t  modifier;     // HID 修饰键掩码
    uint8_t  keycode[6];   // HID 键码，最多 6 键
    uint16_t timestamp;    // 时间戳（ms 低16位）
    uint8_t  seq_num;      // 序列号
    uint8_t  crc8;         // CRC8 校验
} key_frame_t;
```

**音频帧 (133 字节)**
```c
typedef struct __attribute__((packed)) {
    uint8_t  frame_type;                 // = FRAME_TYPE_AUDIO
    uint8_t  seq_num;                    // 序列号
    uint16_t timestamp;                  // 时间戳
    uint8_t  audio_data[128];            // 128 字节 PCM (64 采样 × 2 字节)
    uint8_t  crc8;
} audio_frame_t;
```

**Token 状态帧 (154 字节)**
```c
#define TOKEN_NAME_LEN   20
#define TOKEN_MAX_ITEMS   5

typedef struct __attribute__((packed)) {
    char     name[20];        // 服务名, 如 "OpenAI Codex"
    uint32_t used;            // 已用 token
    uint32_t total;           // 总配额
    uint16_t percent_x10;     // 百分比×10 (847 = 84.7%)
} token_item_t;               // 30 字节

typedef struct __attribute__((packed)) {
    uint8_t      frame_type;  // = FRAME_TYPE_TOKEN_STATUS
    uint8_t      count;       // 有效条目数
    uint8_t      seq_num;
    token_item_t items[5];    // 5 × 30 = 150 字节
    uint8_t      crc8;
} token_status_frame_t;
```

**项目状态帧 (154 字节)**
```c
#define PROJECT_NAME_LEN   24
#define PROJECT_MAX_ITEMS   6

typedef enum {
    PROJ_STATUS_PLANNING   = 0x00,  // 蓝色
    PROJ_STATUS_CODING     = 0x01,  // 紫色
    PROJ_STATUS_REVIEW     = 0x02,  // 橙色
    PROJ_STATUS_COMPLETED  = 0x03,  // 绿色
    PROJ_STATUS_ERROR      = 0x04,  // 红色
    PROJ_STATUS_IDLE       = 0x05,  // 灰色
} project_status_code_t;

typedef struct __attribute__((packed)) {
    char    name[24];         // 项目名
    uint8_t status_code;      // project_status_code_t
} project_item_t;             // 25 字节

typedef struct __attribute__((packed)) {
    uint8_t        frame_type;// = FRAME_TYPE_PROJECT_STATUS
    uint8_t        count;
    uint8_t        seq_num;
    project_item_t items[6];  // 6 × 25 = 150 字节
    uint8_t        crc8;
} project_status_frame_t;
```

### 4.3 CRC8 校验

多项式 `0x07`，初值 `0x00`，覆盖帧内除最后 crc8 字节外的所有字节。两端共用 `espnow_crc8()` 内联函数。

> ⚠️ **协议一致性**: `espnow_protocol.h` 必须在 K10 和 Dongle 两端保持完全一致，修改后两端都要重新编译。

## 6. SD 卡 + LVGL 文件系统 (main.h)

### 6.1 初始化流程 (setup 中)

```cpp
sd_spi = new SPIClass(HSPI);
sd_spi->begin(SD_SCLK, SD_MISO, SD_MOSI);
if (SD.begin(SD_CS, *sd_spi, 1000000)) {
    lv_fs_sd_init();       // 注册 LVGL 文件系统驱动
    sd_card_ready = true;
} else {
    sd_card_ready = false; // 触发降级方案
}
```

### 6.2 LVGL 文件系统桥接

`main.h` 实现了 5 个回调函数，把 Arduino `SD` 库桥接到 LVGL 文件系统，挂载为 **S: 盘符**：

| 回调 | 功能 |
|------|------|
| `fs_sd_open_cb` | 打开文件，返回 `File*` |
| `fs_sd_close_cb` | 关闭文件并释放 |
| `fs_sd_read_cb` | 读取字节 |
| `fs_sd_seek_cb` | 定位（SET/CUR/END） |
| `fs_sd_tell_cb` | 获取当前位置 |

> 注意: 函数命名为 `lv_fs_sd_init()` / `fs_sd_*`，避免与 LVGL 内置的 `lv_fs_fatfs_init()` 冲突。

LVGL 内置 PNG 解码器，`lv_img_set_src(img, "S:/path.png")` 即可自动从 SD 卡读取并解码显示。

## 7. 按键交互

### 7.1 按键映射

| 按键 | 短按 (<600ms) | 长按 (≥600ms) | 组合 |
|------|--------------|--------------|------|
| **A** (eP5_KeyA) | F2 (0x3B) + 切换音频流 | Enter (0x28) 确认 | A+B 同时 2s = 演示模式 |
| **B** (eP11_KeyB) | 切换界面 (0→1→2→3→4→5→0) | 连续 Backspace (0x2A, 100ms间隔) | - |

### 7.2 边沿检测原理

- 按下时记录 `press_time_a/b`（不立即动作）
- 释放时计算持续时间判断短按/长按
- 按键 B 长按在持续按住期间每 `REPEAT_INTERVAL_MS`(100ms) 重复发送
- A+B 组合键在 `loop()` 开头优先检测，触发后等待释放避免误触发单键逻辑

### 7.3 HID 键码表

| 功能 | 键码 |
|------|------|
| F2 | 0x3B |
| Enter | 0x28 |
| Backspace | 0x2A |
| Esc | 0x29 (未使用) |

### 7.4 send_key 辅助函数

发送一对按下+释放帧（间隔 20ms），封装了帧构建、CRC 计算、ESP-NOW 发送。

## 8. 演示模式（模拟数据）

> ⚠️ **重要说明**: 演示模式注入的是**硬编码的模拟数据**，用于验证 UI 渲染效果。
> 界面 1~5 的**真实数据**目前没有来源——需要开发**上位机程序**才能打通（见第 8.3 节）。
> 当前"六界面已验证"= UI 布局/渲染/模拟数据注入已验证，**≠ 真实数据已打通**。

### 8.1 触发方式

同时按住 A+B 保持 2 秒 → `inject_demo_data()`

### 8.2 注入的模拟数据

- **Token**: 4 个 AI 服务（OpenAI Codex 84.7% 红色 / Claude Opus 62.5% / Claude Sonnet 62.3% / Cursor 39.2%）
- **Project**: 5 个项目（Smart Todo App/AI Chat Assistant/Voice Keyboard/Weather Dashboard/Desktop Pet）

触发后自动跳转到界面 1 (Token Usage)。

这些数据全部写死在 `inject_demo_data()` 函数里，不随电脑上 AI 软件的实际状态变化。

### 8.3 上位机程序（待开发）

要让界面显示**真实数据**，必须开发一个运行在 PC 上的上位机程序，完整数据链路：

```
Claude Code / Cursor 等 AI 软件的运行状态
        │
        │ ① 上位机读取（读日志/调API/抓取界面）← 待开发，无法省略
        ▼
   PC 上位机程序 (Python 等)
        │ ② USB 串口发送（打包成状态帧）
        ▼
   Dongle (ESP32)
        │ ③ Dongle 固件转发（串口收 → ESP-NOW 发）← 待开发
        ▼ ESP-NOW (FRAME_TYPE_TOKEN_STATUS / PROJECT_STATUS)
   K10 (本固件，接收端已就绪 ✅)
```

**三个待开发部分**:

| 部分 | 状态 | 说明 |
|------|------|------|
| ① 上位机数据读取 | ❌ 待开发 | 读取 Claude Code 等的 token 用量、项目状态。数据从日志文件/API/界面抓取，**这一步无法省略**——Dongle 无法自己读懂 PC 上软件的状态 |
| ② 上位机 → Dongle 传输 | ❌ 待开发 | Python 通过 USB 串口把状态数据发给 Dongle |
| ③ Dongle 固件转发 | ❌ 待开发 | Dongle 现有固件只做键盘/音频转发，需增加"串口收状态 → 打包状态帧 → ESP-NOW 发给 K10" |
| ④ K10 接收显示 | ✅ 已就绪 | `espnow_recv_cb()` 已能解析 TOKEN/PROJECT 状态帧并刷新界面 |

**关键技术约束**:
- 电脑 WiFi 网卡**无法直接发 ESP-NOW**（Windows 标准驱动不支持原始帧注入），必须经 Dongle 这类 ESP32 设备中转
- 上位机读取程序无法省略，因为 AI 软件状态只存在于 PC 本地，Dongle/K10 无从得知

**上位机需要提供的数据格式**（对应协议帧）:
- Token 数据: 服务名 + 已用 token + 总配额 + 百分比（最多 5 项）
- 项目数据: 项目名 + 状态码（Planning/Coding/Review/Completed/Error/Idle，最多 6 项）

## 9. 主循环 (loop) 时序

```
loop() 每轮:
  1. A+B 组合键检测（优先，触发演示模式）
  2. 按键 A 短按/长按检测（每 10ms）
  3. 按键 B 短按/长按检测（每 10ms）
  4. 音频采集 + ESP-NOW 发送（streaming 时）
  5. 界面刷新（screen_dirty 时）
  6. AI Status 界面旋转动画（界面5时每 100ms）
  7. lv_task_handler() LVGL 渲染
  8. delay(2) 防看门狗
```

**线程安全**: 所有 LVGL 操作用 `xGuiSemaphore` 互斥锁保护。

1. **动态 GIF**: 界面 5 用 `lv_gif_create()` 播放云朵动画（需 GIF 文件）
2. **SD 卡图片浏览**: 参考 31_png_browser 递归扫描 SD 卡所有图片

### 技术约束
- 电脑 WiFi 网卡无法直接发 ESP-NOW（Windows 不支持原始帧注入），必须经 ESP32 设备中转
- PNG 解码占用临时 RAM ≈ 宽×高×4 字节（240×320 ≈ 300KB，PSRAM 充足）
