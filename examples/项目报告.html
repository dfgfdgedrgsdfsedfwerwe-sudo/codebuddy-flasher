一句话总结

这是 DFRobot 行空板 K10（UNIHIKER K10）的官方 Arduino 教学示例仓库。它把 屏幕点亮、传感器读取、音频播放、LVGL 图形界面、小游戏 等十几个独立 Demo 集中在一个 PlatformIO 工程里，通过 platformio.ini 里的一行 default_envs 来切换当前编译哪个示例——每次只编译一个。

硬件平台

主控 MCU

ESP32-S3（esp32-s3-devkitc-1），带 PSRAM（qio_opi 内存模式），启用 USB CDC 启动。

显示屏

ILI9341 面板，240×320，走 SPI2 总线。引脚：SCLK=12、MOSI=21、DC=13、CS=14，40MHz 写速率，启用 DMA。

IO 扩展芯片

XL95x5（I2C）负责扩展 GPIO——按键 A/B、屏幕背光复位等都挂在扩展芯片上，而非直接连 MCU。

板载外设

AHT20 温湿度、SC7A20H 加速度计、I2S 音频输出、SD 卡、麦克风（语音识别模型 srmodels.bin）。

核心工作流：一行切换示例

整个工程最关键、也最容易踩坑的一点——你不是选择"编译全部"，而是通过 default_envs 指定当前编译哪一个 Demo。src_dir 会跟着这个值自动指向对应的示例目录：

; platformio.ini
[platformio]
default_envs = 30_lvgl_Gif        ; ← 改这一行来切换示例
src_dir = examples/${platformio.default_envs}   ; 源码目录随之自动切换
修改 default_envs → pio run 编译 → pio run -t upload 烧录 → pio device monitor 看串口

共享的硬件抽象层

多数示例复用同一套初始化模板，理解这三块就能看懂大部分 Demo：

K10_Lcd

位于 lib/bsp_handler/Lcd_handler.hpp，继承 LovyanGFX 的 LGFX_Device，把 ILI9341 的引脚、SPI 频率、DMA 全部硬编码好。

XL95x5 扩展芯片

按键、背光复位等 GPIO 都经过 I2C 扩展芯片，lvgl_begin() 里先初始化它并复位屏幕背光。

LVGL 初始化模板

固定套路：在 PSRAM 里分配双绘制缓冲区 → 注册 my_disp_flush（DMA 刷屏）→ 用 xGuiSemaphore 互斥锁包裹 lv_task_handler()。

⚠️ 已知问题与注意事项

拉取后无法直接编译。 README 明确指出：Arduino_DriveBus 和 ESP32_JPEG 这两个库下载后是空文件夹，需要从仓库根目录的 lib.zip（约 1.7 MB）中手动解压找回，否则编译报错。
子模块需初始化。 lvgl 和 LovyanGFX 是 git 子模块（见 .gitmodules）。克隆后需执行 git submodule update --init --recursive。
32_DEMO_MJPEG 有额外依赖。 该示例需要手动把 ESP32_JPEG 库放进 lib 目录，并链接 libesp_codec.a（见 platformio.ini 中该 env 的 build_flags）。
  • 使用自定义 16MB 分区表 large_spiffs_16MB.csv：factory 5MB、model(spiffs) 4.5MB、voice_data(fat) 2.5MB——为语音模型和资源预留了大空间。
  • 没有自动化测试框架，test/ 目录仅含 README。验证方式 = 烧录到真实硬件观察。
  • 串口波特率 115200，烧录速率 921600。
  • 仓库含中文目录 sd卡文件（SD 卡示例所需的媒体资源）。

整体评价

这是一个组织清晰的官方硬件教学示例库，而非单一应用。设计目标是让用户逐个体验行空板 K10 的各项能力——从最基础的点屏，到 LVGL 图形应用，再到音频与 AI 人脸识别。工程质量的关注点在"每个示例能独立跑通"，代价是需要手动处理库依赖（lib.zip、子模块），首次上手的主要障碍集中在环境准备而非代码本身。配套教程见 README 中的 DFRobot 论坛链接。
