# Agent 工作流可视化 - 端到端测试计划

**日期**: 2026-09-03  
**版本**: 1.0

---

## 测试环境

### 硬件
- **ATK BOX**: 正点原子 ESP32-S3 BOX（COM11 烧录, COM12 串口输出）
- **Dongle**: ESP32-S3 Dongle（COM6）
- **连接**: Dongle USB 连接 PC，ATK BOX 与 Dongle 通过 ESP-NOW 2.4GHz 无线通信

### 软件
- **固件版本**: 52_codebuddy_ai_box（包含 Agent 状态机 + 审批界面）
- **PC 工具**: `agent_status_bridge.py` v1.0
- **Python**: 3.7+, pyserial

### 阶段 2: Agent 状态推送测试

**目标**: 验证 0x0C Agent 状态帧能正确推送到 ATK BOX 并显示

#### 2.1 启动 Agent 桥接
```bash
cd pc_tools
python agent_status_bridge.py COM6 --interval 2
```

**预期终端输出**:
```
=== Agent Status Bridge ===
串口: COM6
刷新间隔: 2s
监听 Claude Code 会话...
```

#### 2.2 测试 IDLE 状态
**操作**: 确保无活跃 Claude Code 会话（关闭所有 Claude Code 窗口或等待 15 分钟超时）

**预期**:
- 终端输出: `[→] Agent: IDLE | No active session`
- ATK BOX 串口: `Agent status received: state=0 (IDLE)`
- ATK BOX 屏幕: 显示 "Agent: Idle" 或无特殊状态横幅

#### 2.3 测试 THINKING 状态
**操作**: 打开 Claude Code，发送一条消息（如 "hello"）

**预期**:
- 终端输出: `[→] Agent: THINKING | Thinking...`
- ATK BOX 串口: `Agent status received: state=1 (THINKING)`
- ATK BOX 屏幕: 显示 "Agent: Thinking..." + 任务描述

#### 2.4 测试 RUNNING 状态
**操作**: 让 Claude Code 执行工具调用（如 "read the README file"）

**预期**:
- 终端输出: `[→] Agent: RUNNING | Running: Read`
- ATK BOX 串口: `Agent status received: state=2 (RUNNING) task="Running: Read"`
- ATK BOX 屏幕: 显示 "Agent: Running: Read" + 详情

#### 2.5 测试 DONE 状态
**操作**: 等待 Agent 完成任务，会话空闲

**预期**:
- 终端输出: `[→] Agent: DONE | Idle`
- ATK BOX 串口: `Agent status received: state=3 (DONE)`
- ATK BOX 屏幕: 显示 "Agent: Done" 或回到默认界面

**验证点**:
- ✅ 状态变化实时反映（2 秒延迟内）
- ✅ 无重复发送相同状态（缓存机制生效）
- ✅ 串口无 CRC8 校验错误

### 阶段 3: 审批交互测试

**目标**: 验证 0x0D 审批请求帧推送 + 0x0E 审批回执接收

#### 3.1 触发审批请求
**操作**: 让 Claude Code 调用 `AskUserQuestion` 工具（如 "应该继续这个操作吗？"）

**预期**:
- 终端输出: `[→] 审批请求: Should I proceed?`
- ATK BOX 串口: `Agent approval request received: task_id=12345`
- ATK BOX 屏幕: **自动切换到 Screen 8**（审批界面）
  - 标题显示: "Should I proceed?"
  - 描述显示: "Review required"
  - 三个触摸按钮: OK / UP / DOWN
- 提示音: **嘟嘟两声**（TONE_APPROVAL）

#### 3.2 测试 APPROVE（批准）
**操作**: 触摸 OK 按钮

**预期**:
- ATK BOX 串口: `Approval reply task=12345 action=APPROVE sent`
- 提示音: **上升音**（TONE_DONE）
- 屏幕: 返回到之前的屏幕（如 Screen 5）
- 状态机: `g_workflow_state` → `WORKFLOW_STATE_AGENT_RUNNING`

**PC 端接收**（当前版本未实现）:
- ⚠️ `agent_status_bridge.py` 需要添加串口读取循环来接收 0x0E 帧

#### 3.3 测试 REJECT（拒绝）

**预期**:
- ATK BOX 串口: `Approval reply task=12345 action=REJECT sent`
- 提示音: **低沉咚声**（TONE_REJECT）
- 屏幕: 返回到之前的屏幕
- 状态机: `g_workflow_state` → `WORKFLOW_STATE_READY`

#### 3.4 测试 VIEW_DIFF（查看详情）

### 阶段 5: 状态机完整流程

**目标**: 验证 `workflow_state_t` 状态机按预期转换

#### 5.1 完整流程
```
HOME (启动)
  ↓
READY (空闲, Screen 5)
  ↓ (按住 A 开始录音)
LISTENING (录音中, 显示麦克风 + 计时)
  ↓ (松开 A)
TRANSCRIBING (转写中, 数据发送)
  ↓ (PC 端识别完成)
AGENT_RUNNING (Agent 工作中, 接收 0x0C RUNNING 状态)
  ↓ (收到 0x0D 审批请求)
APPROVAL (Screen 8, 等待用户操作)
  ↓ (触摸 OK)
AGENT_RUNNING (继续工作)
  ↓ (Agent 完成, 收到 0x0C DONE 状态)
DONE (完成, 可能播放 TONE_DONE)
  ↓ (超时或按键)
READY
```

**验证点**:
- ✅ 每次状态转换在串口日志中可见
- ✅ 状态转换触发对应的界面切换
- ✅ 审批态阻塞常规按键，但允许 LVGL 刷新
- ✅ 超时或完成后正确返回 READY

#### 5.2 异常路径
**测试场景**:
1. **录音中退出**: LISTENING 态单击音量+ → 立即回 READY（迟到的识别不上屏）
2. **审批超时**: APPROVAL 态等待 60s → 发 TIMEOUT 回执 → 回 READY
3. **ESP-NOW 断开**: 模拟 Dongle 断电 → 状态推送失败 → 显示离线横幅（未来实现）

**预期**:
- ✅ 异常不导致状态机卡死
- ✅ 超时机制正确触发
- ✅ 错误提示音（TONE_ERROR）在合适时机播放
