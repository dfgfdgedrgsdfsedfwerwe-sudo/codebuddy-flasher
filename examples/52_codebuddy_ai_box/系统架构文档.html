CodeBuddy AI BOX 系统架构文档

更新日期：2026-09-09  |  版本：CodeBuddy Bridge v1.0.0

一套「AI 编程助手 ←→ 硬件交互终端」的双向系统：状态可视化 + 决策审批 + 音频键盘。

一、系统总览

CodeBuddy AI BOX 提供三大核心能力：

上行 · 状态可视化

把 Claude Code 的 Token 用量、项目进度、AI 情绪、当前工具实时推送到 ATK BOX 屏幕。

下行 · 决策审批

AI 遇岔路口时推送选择题到触摸屏，用户点选后结果回传，AI 继续执行。

音频 + 键盘

ATK BOX 麦克风与按键经 Dongle 转为 USB 声卡 + HID 键盘送到 PC。

   Python 工具集                  USB 复合设备                   触摸屏 + 麦克风

二·五、ATK BOX 固件详解 终端层

本章详细展开终端层的实现，包括 7 个 UI 界面、按键/触摸交互、硬件驱动、状态机逻辑。

A. 七大 UI 界面（LVGL）

ATK BOX 运行 7 个全屏 LVGL 界面，按键 B (K1) 短按循环切换，顺序为 {5→2→1→3→4→6→0}。

界面 ID名称主要内容数据来源交互能力
0ESP-NOW Status连接状态、丢包率、MAC本地统计无（只读）
1Token UsageAI 服务 Token 用量（≤5）PC 推送 0x07✅ 演示：A 短按高亮
2Coding Status项目进度列表（≤6）PC 推送 0x08无
3Product Inspo灵感卡片 + 打字机演示数据✅ 演示：A 重启动画
4User Profile用户照片 + 姓名SD 卡 D:/user.png✅ 演示：A 切换头像
5AI Status动画云朵 + 情绪PC 0x09 或本地循环✅ 点击切换情绪
6TouchTest触摸测试（坐标+绿点）实时触摸✅ 画点验证校准
界面 7 - Decision UI （不在循环中）
PC 推送 0x0A 时临时覆盖当前界面，显示标题 + ≤4 选项，用户触摸选择后发送 0x0B 回执，自动返回原界面。

A.5 界面 5 - AI Status（启动默认界面）

功能：实时显示 AI 工作状态，用动画云朵 + 表情表达情绪。

情绪枚举值眉毛嘴巴默认文字触发场景
THINKING0上扬（Y-4px）小闭嘴"Thinking..."用户提交 prompt
CODING1皱眉（Y+5px）动嘴说话（250ms 开合）"Coding..."工具执行中
DONE2平眉（Y±0）宽笑脸（26×14px）"Done!"任务完成
  • 本地模式（默认）：每 4 秒自动循环切换情绪
  • 外部模式：收到 PC 的 0x09 帧后覆盖本地循环，15 秒无新帧则恢复本地
  • 动画细节：眼睛每 3 秒眨一次，CODING 状态下嘴巴 250ms 开合
  • 触摸交互：点击云朵区域 → 手动切换到下一个情绪

三、PC 端软件架构 重点

PC 端采用「daemon + 多客户端」分层设计，围绕一个独占串口的守护进程展开。

3.2 关键设计：为什么要 daemon？

串口只能被一个进程独占。若每个工具都直接开 COM6 会互相抢占报 PermissionError。因此引入 daemon 作为唯一持有串口的进程，其他工具通过 TCP IPC 向它发请求。

⚠️ 重要区分 mcp_atkbox_server.py 不是 daemon，它是 MCP stdio 客户端，自己去连 47100。「MCP 工具能用」不等于「daemon 在跑」——daemon 需单独启动，或由 CodeBuddyBridge.exe GUI 托管。

3.3 IPC 协议（TCP 47100）

单行 JSON，请求/响应模式，三种类型：

type请求示例响应行为
statusstate/tool/detail{"ok":true}非阻塞，1s 节流
decisiontitle/options[≤4]{"chosen":0-3}阻塞≤40s，255=取消
approvaltool/file/preview{"decision":"allow/deny"}阻塞等回执

三·五、两大客户端功能详解 Hook / MCP

客户端层最重要的两个入口是 Claude Hook 和 MCP 工具。Hook 是「被动监听」Claude 运行自动推送状态/拦截审批；MCP 是「主动调用」让 Claude 在硬件上问问题。

A. Claude Hook 客户端（hook_client.py）

定位：瘦客户端，把 Claude Code 触发的 Hook 事件翻译成 IPC 请求发给 daemon。每次触发都是一次性进程（启动 → 连 47100 → 发请求 → 退出）。

调用方式：python hook_client.py <event_type>，Claude Code 通过 stdin 传入 JSON（包含 prompt、tool_name、tool_input 等）。

A.1 四个正式 Hook 事件

事件Claude 触发时机hook_client 行为发送的 IPC是否阻塞
user_prompt用户提交一条 prompt取 prompt 前 50 字 → 发 THINKING 状态status/THINKING否（静默退出）
pre_tool工具执行前见下方拦截逻辑approval 或 statusWrite/Edit 类阻塞
post_tool工具执行后提取目标文件/命令 → 发 RUNNING 状态status/RUNNING否
stop一轮任务完成发 DONE 状态status/DONE否

状态流转效果：用户提问 → BOX 显示 THINKING（思考）→ 每次工具调用 → 显示 RUNNING + 工具名（工作中）→ 任务结束 → 显示 DONE（完成）。ATK BOX 的 AI 云朵表情随之切换。

A.2 pre_tool 的审批拦截（核心安全能力）

pre_tool 事件对写操作工具做拦截（matcher: "Write|Edit|NotebookEdit"）：

  1. 提取 file_path（或 notebook_path）和 content 前 200 字作为预览
  2. 向 daemon 发 approval 请求（阻塞等待用户在 BOX 上批准/拒绝）
  3. 根据回执输出 Claude Code 的权限决策 JSON：
    • 批准 → {"permissionDecision": "allow"}（工具正常执行）
    • 拒绝 → {"permissionDecision": "deny"}（工具被阻止）
安全机制 这意味着：AI 每次要写文件，都会先在你的硬件盒子上弹出审批，你点"允许"它才写。daemon 侧还会按文件路径推断风险等级（test→低，config/settings→中，其余→高）。

A.3 AskUserQuestion 监测

当 Claude 调用内置的 AskUserQuestion 工具时，hook 会监测但不拦截：把问题数量记到日志、发一条 RUNNING 状态，然后放行（不输出 JSON = 默认 allow）。这是为将来"把 Claude 的提问自动转到硬件"预留的探针。

A.4 实验事件探针

代码里还有一批实验性事件处理（notify_agent_input、elicitation、permission_request 等），作用是探测 AskUserQuestion 到底触发哪个 hook——把完整 hook_input 记进 daemon 日志和 stderr，不干预流程。属于研发调试用，正式功能不依赖。

A.5 Hook 安装（install_hooks.py）

  • 把 4 个 hook（UserPromptSubmit / PreToolUse / PostToolUse / Stop）合并进 ~/.claude/settings.json，保留用户已有字段
  • 安装前自动备份为 settings.json.backup
  • --uninstall 可干净移除
  • PyInstaller 兼容：打包成 exe 后，__file__ 指向临时目录 _MEIxxx（exe 退出即消失）。安装脚本会把 hook_client.py 复制到永久目录 ~/.codebuddy_bridge/，再把该永久路径写进 settings，避免 exe 关闭后 hook 失效。

B. MCP 工具服务（mcp_atkbox_server.py）

定位：一个 MCP stdio server，向 Claude 暴露一个可主动调用的工具 ask_on_atkbox。与 Hook 相反，这是 Claude "想问就问"的主动通道。

⚠️ 再次强调 MCP server 不持有串口，它也是 daemon 的客户端，收到调用后连 47100 转发 decision 请求。

B.1 暴露的工具：ask_on_atkbox

项规格
功能在 ATK BOX 硬件上显示一道选择题，等用户触摸选择
入参title（≤31 字符）、options（1-4 项，每项 ≤23 字符）
返回用户所选项的索引 0-3 及文本；255 = 取消/超时
超时40 秒
语言仅英文（中文触发编码 bug）

B.2 实现的 MCP 协议方法

server 是一个 stdin 逐行读 JSON-RPC 的循环，实现了标准 MCP 握手：

方法作用
initialize返回协议版本 2024-11-05、serverInfo（name=atkbox）、capabilities
tools/list列出唯一工具 ask_on_atkbox 及其 inputSchema（title + options 的类型约束）
tools/call执行调用：连 daemon 发 decision → 拿 chosen → 组装成人类可读的 content 文本返回
未知方法返回 -32601 Method not found

B.3 调用链

Claude 决定问用户 → tools/call ask_on_atkbox(title, options)
  → send_decision_to_daemon() 连 127.0.0.1:47100
    → daemon 发 0x0A → Dongle → BOX 显示 Screen 7
      → 用户触摸 → BOX 发 0x0B → daemon → MCP
        → 返回 "User chose option N: <文本>" 给 Claude

B.4 MCP 安装（install_mcp_atkbox.py）

  • 写入 ~/.claude.json 的 mcpServers 字段（Claude Code 2.1.206+ 实际读取位置）
  • 配置形如 {"atkbox": {"command":"python","args":[server路径],"type":"stdio"}}
  • 同样有 PyInstaller 永久化逻辑：把 mcp_atkbox_server.py 复制到 ~/.codebuddy_bridge/
  • 安装后需完全重启 Claude Code（exit 所有窗口再启动），/mcp 验证工具出现

五、通信协议规范

5.1 串口帧格式（PC ↔ Dongle）

┌──────┬──────┬─────────┬─────────────┬───────────┐
│ 0xA5 │ 0x5A │ len(1B) │  payload    │ outer_crc8│
└──────┴──────┴─────────┴─────────────┴───────────┘
                          └─ ESP-NOW payload (含 inner_crc8)
  • 双层 CRC8（多项式 0x07）：外层校验串口，内层校验 ESP-NOW 载荷
  • 帧间延迟：连续发送需间隔 0.5s，Dongle 转发无缓冲

5.2 帧类型总表

帧类型值方向用途
KEY0x01BOX→PC按键事件（HID）
AUDIO0x02BOX→PC音频数据（16kHz 单声道）
FEC0x03BOX→PC音频 XOR 冗余
PAIR/ACK0x04/05双向配对握手
HEARTBEAT0x06双向心跳
TOKEN_STATUS0x07PC→BOXToken 用量（≤5）
PROJECT_STATUS0x08PC→BOX项目进度（≤6）
AI_STATE0x09PC→BOXAI 情绪（云朵表情）
DECISION_REQ0x0APC→BOX决策请求（≤4 选项）
DECISION_REPLY0x0BBOX→PC决策回执（0-3/0xFF）
AGENT_STATUS0x0CPC→BOXAgent 工作状态
APPROVAL_REQ0x0DPC→BOX审批请求
APPROVAL_REPLY0x0EBOX→PC审批回执

六、典型使用流程

6.1 启动系统

# 方式 A：GUI（推荐给最终用户）
dist/CodeBuddyBridge.exe          # 双击，图形界面启动 daemon

# 方式 B：命令行（开发调试）
python atkbox_daemon.py --port COM6

6.2 决策交互（AI → 用户）

Claude 调用 MCP 工具 ask_on_atkbox
  → mcp_atkbox_server.py 连 47100
    → daemon 发 0x0A 决策帧
      → Dongle → ESP-NOW → BOX 显示 Screen 7 决策界面
        → 用户触摸选择
          → BOX 发 0x0B 回执 → daemon → MCP → Claude 拿到 chosen 索引

6.3 状态可视化（用户 → BOX）

realtime_monitor.py 或 daemon 后台线程
  → 读 ~/.claude/ 的 Token/项目/AI 状态
    → 每 30s 推送 0x07/0x08/0x09 帧
      → BOX 屏幕实时更新

十、技术亮点与创新

1. 双向硬件交互

上行状态可视化 + 下行决策审批。降低注意力切换成本，写文件前物理设备批准，云朵表情跟随 AI 节奏。

2. daemon + 多客户端

单一守护进程持有串口，所有工具通过 IPC 共享。Hook/MCP/监控/游戏同时运行互不干扰。

3. PyInstaller 永久化

检测 frozen 标志，自动复制脚本到永久目录，exe 可关闭而 hook 持久生效。

4. 交互式游戏开发

用硬件做设计工具：6 步触摸选择生成完整 2048 游戏，全流程 <2 分钟零手动编码。
