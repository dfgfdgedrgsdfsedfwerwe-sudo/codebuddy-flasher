## 一、项目概述

### 1.1 原项目
- **来源**: https://github.com/V4C38/esp32-fluidbox
- **平台**: ESP-IDF (FreeRTOS + SPI LCD)
- **功能**: 实时流体物理模拟 + IMU倾斜控制
- **核心算法**: Navier-Stokes方程求解器 (80×106粒子网格)

### 1.2 目标硬件
| 组件 | ATK BOX 规格 |
|------|-------------|
| MCU | ESP32-S3 @ 240MHz |
| RAM | 327KB (SRAM) + 2MB PSRAM |
| Flash | 16MB |
| LCD | ST7789 240×320, **8080并口** (非SPI) |
| 触摸 | **CHSC5432 电容触摸**, I2C 0x2E, 10点触控 |
| 背光 | XL9555 I2C GPIO扩展器, P0.7控制 |
| 音频 | ES8311 (本项目未用) |

### 1.3 移植目标
✅ 保留原核心物理引擎不修改  
✅ 适配ATK BOX硬件 (8080并口 + DMA)  
✅ **利用触摸屏替代IMU**, 实现更直观的交互  
✅ Arduino框架编译通过  
⏳ 硬件实测验证

## 二、技术实现

### 2.1 显示驱动适配 (atk_display.cpp/h)

**关键差异**:
| 原版 (ESP-IDF SPI) | ATK版 (LovyanGFX 8080) |
|-------------------|----------------------|
| `spi_device_queue_trans()` | `pushImageDMA()` |
| 手动管理DMA信号量 | 库内部自动同步 |
| QSPI字节序需手动SWAP | 库自动处理 |
| 条帯缓冲: malloc | PSRAM分配 |

**DMA流水线**:
```
8条帯 (240×40) × 2缓冲 = 307KB 总缓冲
条帯0渲染 → 条帯1传输 (并行)
FPS ~30, 无阻塞
```

### 2.2 触摸交互实现 (atk_touch_fluid.c/h) ⭐

**核心创新**: 将触摸输入映射为物理力场

#### 驱动层
```c
// CHSC5432 I2C通信 (引脚: SDA=17, SCL=18)
#define TOUCH_I2C_ADDR 0x2E
#define TOUCH_MAX_POINTS 10

void touch_init() {
    Wire.begin(17, 18, 400000);
    // 读取固件ID验证连接
}

void touch_update(touch_point_t points[10]) {
    // 读取寄存器0x0F: 触摸点数
    // 循环读取每个点的 X/Y 坐标 (12bit)
}
```

#### 物理映射
```c
// 屏幕坐标 240×320 → 流体网格 80×106
float grid_x = (touch_x / 240.0) * 80;
float grid_y = (touch_y / 320.0) * 106;

// 在触摸点半径25px内注入徑向力
for (相邻网格点) {
    float force = 800.0 / (1.0 + distance);
    float dx = (x - grid_x) / distance;
    float dy = (y - grid_y) / distance;
    
    velocity_x[idx] += force * dx;  // 向外推
    velocity_y[idx] += force * dy;
}
```

**效果**:
- ✅ 单指触摸 → 局部产生波纹
- ✅ 滑动 → 连续注入力形成涡流
- ✅ 多指同时触摸 → 多个独立力场叠加
- ✅ 松手 → 流体在粘度作用下逐渐静止

**与原IMU方案对比**:
| 维度 | IMU倾斜 | 触摸交互 |
|------|---------|---------|
| 力场类型 | 全局重力 (单一方向) | 局部徑向力 (多点) |
| 直觉性 | 需要理解"倾斜→重力"映射 | **直接拨动流体** |
| 演示价值 | 设备静止时无变化 | **主动操控, 更有趣** |
| 技术难度 | 读加速度计简单 | **屏幕坐标→网格力场映射** |

## 三、关键技术决策

### 3.1 为何选择触摸而非IMU？

**原因**:
1. **ATK BOX无板载IMU** (原版用的是其他开发板)
2. **触摸屏是ATK BOX的核心特性** (CHSC5432专业触摸IC)
3. **交互直觉性更强**: 手指直接"拨动"流体 vs. 倾斜设备间接控制
4. **演示价值更高**: 观众可以上手互动, 而非被动观看

### 3.2 为何使用LovyanGFX？

**原因**:
1. 已有成熟的ATK BOX配置 (参考52例)
2. 自动处理8080并口DMA细节
3. Arduino生态兼容性好
4. 无需移植ESP-IDF SPI驱动代码

### 3.3 为何保留原物理引擎？

**原因**:
1. **Navier-Stokes求解器是核心IP**, 稳定且高效
2. 只需适配输入/输出接口, 无需理解流体力学算法
3. 便于与原项目比对调试
